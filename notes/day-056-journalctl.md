# Day 056 - Log Management with `journalctl`

## 🧠 Introduction

When something goes wrong on a Linux system, the first place an administrator checks is the **system logs**.

Logs record important events such as:

- Service startups and shutdowns
- Login attempts
- System errors
- Hardware events
- Security warnings
- Kernel messages

On modern Linux systems that use **systemd**, logs are managed by the **systemd journal**.

The primary command used to view these logs is:

```text
journalctl
```

Learning `journalctl` is essential because troubleshooting almost always begins with checking the logs.

---

# Viewing All Logs

Display every log entry:

```bash
journalctl
```

Because there may be thousands of entries, you can scroll using:

```text
↑ ↓

Page Up

Page Down
```

Press:

```text
q
```

to quit.

---

# Display the Most Recent Logs

Show the latest log entries:

```bash
journalctl -n 20
```

Option:

```text
-n = Number of lines
```

Example:

```bash
journalctl -n 50
```

Display the last 50 log messages.

---

# Follow Logs in Real Time

Similar to:

```bash
tail -f
```

Use:

```bash
journalctl -f
```

New log entries appear immediately as they are generated.

This is useful when debugging running services.

---

# Viewing Logs for a Specific Service

Display logs generated by SSH:

```bash
journalctl -u ssh
```

View Nginx logs:

```bash
journalctl -u nginx
```

Docker logs:

```bash
journalctl -u docker
```

Option:

```text
-u = Unit (service)
```

---

# Filter Logs by Time

Show today's logs:

```bash
journalctl --since today
```

Display logs from the last hour:

```bash
journalctl --since "1 hour ago"
```

Show logs between two times:

```bash
journalctl \
--since "2026-07-20 10:00" \
--until "2026-07-20 12:00"
```

Time filters make it much easier to investigate specific incidents.

---

# Viewing Boot Logs

Display logs from the current boot:

```bash
journalctl -b
```

View the previous boot:

```bash
journalctl -b -1
```

Older boots:

```bash
journalctl -b -2
```

This is especially useful after unexpected crashes or failed startups.

---

# Filter by Priority

Journal messages have priority levels.

Show only errors:

```bash
journalctl -p err
```

Warnings:

```bash
journalctl -p warning
```

Critical errors:

```bash
journalctl -p crit
```

Priority levels include:

```text
emerg

alert

crit

err

warning

notice

info

debug
```

---

# View Kernel Messages

Display only kernel logs:

```bash
journalctl -k
```

These messages include:

- Hardware detection
- Driver information
- Disk events
- Boot messages

---

# Disk Usage

Check journal size:

```bash
journalctl --disk-usage
```

Example:

```text
Archived and active journals take up 180 MB.
```

---

# Cleaning Old Logs

Delete logs older than seven days:

```bash
sudo journalctl --vacuum-time=7d
```

Limit journal size:

```bash
sudo journalctl --vacuum-size=200M
```

These commands help manage disk space on long-running servers.

---

# Real-World Examples

View SSH logs:

```bash
journalctl -u ssh
```

Watch Docker logs:

```bash
journalctl -fu docker
```

Check today's events:

```bash
journalctl --since today
```

Find recent errors:

```bash

journalctl -b -1
```

---

# Common Mistakes

### Forgetting Root Permissions

Some system logs require elevated privileges.

Instead of:

```bash
journalctl
```

use:

```bash
sudo journalctl
```

to ensure you can access all entries.

---

### Reading Too Many Logs

Instead of viewing the entire journal:

```bash
journalctl
```

filter by:

- Service
- Time
- Priority
- Boot

This makes troubleshooting much faster.

---

### Ignoring Previous Boot Logs

If a server crashed overnight:

```bash
journalctl -b
```

shows only the current boot.

Use:

```bash
journalctl -b -1
```

to investigate the previous boot.

---

# Why `journalctl` Matters

Imagine your web server suddenly stops responding.

A practical troubleshooting workflow is:

Check the service status:

```bash
systemctl status nginx
```

Read the service logs:

```bash
journalctl -u nginx
```

Filter for errors:

```bash
journalctl -u nginx -p err
```

Follow logs while restarting the service:

```bash
journalctl -fu nginx
```

Within minutes, you can identify configuration mistakes, permission problems, or application crashes.

This is why `journalctl` is one of the most valuable tools for Linux administrators.

---

# 🎯 Summary

`journalctl` is the standard log viewer for Linux systems using **systemd**.

Common commands:

```bash
journalctl

journalctl -n 20

journalctl -f

journalctl -u nginx

journalctl -fu docker

journalctl --since today

journalctl -b

journalctl -b -1

journalctl -p err

journalctl -k

journalctl --disk-usage

sudo journalctl --vacuum-time=7d
```

Important options:

```text
-f              Follow logs in real time

-u              View logs for a service

-b              View boot logs

-p              Filter by priority

-k              Show kernel logs

--since         Filter by start time

--until         Filter by end time

-n              Show recent entries
```

Mastering `journalctl` enables you to diagnose service failures, investigate system crashes, monitor live events, analyze boot problems, and efficiently troubleshoot Linux systems.
